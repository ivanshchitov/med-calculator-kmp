# План: PWA-версия MedCalculator для iOS

Дата: 2026-11-21
Статус: утверждён

## Цель

Добавить в проект web-таргет `wasmJs`. Собрать PWA, которая:

- открывается на iPhone в Safari;
- устанавливается на экран «Домой»;
- работает офлайн после первого онлайн-запуска;
- сохраняет настройки;
- не меняет поведение Android и iOS.

Этап 0 (spike на iPhone) пропущен по решению владельца проекта.

## Решения

- **Вариант B:** web без Room.
- **Room 2.8.4** остаётся только на Android и iOS.
- **`nonWebMain`** — промежуточный source set для мобильного Room-слоя.
- **Web-данные:** `medications.json` напрямую, без SQLite и OPFS.
- **Настройки web:** DataStore 1.3.0 + `WebLocalStorage`.
- **Хостинг:** Yandex Object Storage, apex-домен через Yandex Cloud DNS.
- **Домен:** заглушка `<domain>`.
- **COOP/COEP и `_headers` не нужны.**
- **iOS 27** — WasmGC поддерживается.

## Архитектура данных

```text
Android/iOS: UI → UseCases → MedicationRepositoryImpl → Room
Web:         UI → UseCases → WebMedicationRepository → medications.json
Все:         UI → PreferenceManager → DataStore → файл / localStorage
```

## Этап 1. Source sets и DI

### 1.1. Создать `nonWebMain`

Иерархия source sets:

```text
commonMain
   ├── nonWebMain
   │      ├── androidMain
   │      └── iosMain
   └── wasmJsMain
```

В `shared/build.gradle.kts`:

```kotlin
val nonWebMain by creating {
    dependsOn(commonMain.get())
}
androidMain.get().dependsOn(nonWebMain)
iosMain.get().dependsOn(nonWebMain)
```

### 1.2. Перенести Room-слой

Перенести из `commonMain` в `nonWebMain`:

- `data/local/AppDatabase.kt`
- `data/local/DatabaseInitializer.kt`
- `data/local/MedicationDao.kt`

- `data/local/DosageRegimenEntity.kt`
- `data/local/TypeConverters.kt`
- `data/local/RouteUnitMappers.kt`
- `data/local/DataImportConverter.kt`

Оставить в `commonMain`:

- `data/local/DataImportModels.kt`

- `data/repository/LocaleRepositoryImpl.kt`
- `data/repository/PreferencesRepositoryImpl.kt`
- `data/PreferenceManager.kt`
- `data/DataStore.kt`
- все use cases, UI и domain.

### 1.3. Зависимости и KSP

- Перенести `room-runtime` и `sqlite-bundled` в `nonWebMain`.
- Оставить KSP только для Android и iOS:
  - `kspAndroid`;
  - `kspIosX64`;
  - `kspIosArm64`.
- Убрать `kspCommonMainMetadata`.
- Плагин Room оставить `androidx.room` 2.8.4.
- Схему БД не менять.

### 1.4. Разделить Koin

В `commonMain`:

- `initKoin`;
- `preferenceModule`;
- `repositoryModule`;
- `useCaseModule`;
- `viewModelModule`;
- `expect fun platformModule(): Module`;
- `expect suspend fun initializePlatformData(koin: Koin)`.

В `nonWebMain`:

- модуль `MedicationRepository` через Room;
- функция засева БД через `initializeDatabase`.

В `androidMain` и `iosMain`:

- `platformModule` подключает Room-модуль, `getDatabaseBuilder` и `createDataStore`;
- `initializePlatformData` запускает засев БД.

В `wasmJsMain`:

- `platformModule` подключает `WebMedicationRepository` и `createDataStore`;
- `initializePlatformData` ничего не делает.

### 1.5. Добавить wasm-таргет

В `shared/build.gradle.kts`:

```kotlin
@OptIn(org.jetbrains.kotlin.gradle.ExperimentalWasmDsl::class)
wasmJs {
    browser()
    binaries.executable()
}
```

Добавить в `wasmJsMain`:

- `kotlinx-browser`;
- `datastore-core-okio`;
- Compose UI и ресурсы наследуются из `commonMain`.

Создать wasm-actual:

- `Platform.wasmJs.kt`;
- `LocaleHelper.wasmJs.kt`;
- `ui/theme/PlatformTheme.wasmJs.kt`;
- `di/Koin.wasmJs.kt`;
- `data/DataStore.wasmJs.kt`.

Создать `Main.kt`:

```kotlin
fun main() {
    initKoin { }
    ComposeViewport(document.body!!) {
        App()
    }
}
```

### 1.6. Убрать `Dispatchers.IO` из common

В `ChooseMedicationViewModel.kt` убрать:

```kotlin
.flowOn(Dispatchers.IO)
```

Фильтрация дешёвая. На web `Dispatchers.IO` нет. На мобильных он не нужен.

### 1.7. Проверить `AppConfig`

Убедиться, что плагин `buildconfig` генерирует `AppConfig` для wasm. Если нет — заменить на сгенерированный Gradle-задачей исходник.

### 1.8. Проверка этапа

```bash
./gradlew :androidApp:assembleDebug
./gradlew :shared:compileKotlinWasmJs
```

Android и iOS должны работать как раньше.

## Этап 4. Service worker

### 4.1. Precache manifest

Добавить Gradle-задачу после `wasmJsBrowserDistribution`:

- сканирует `shared/build/dist/wasmJs/productionExecutable`;
- формирует `precache-manifest.json`;
- исключает `sw.js`, `precache-manifest.json`, `_headers`;
- версия кеша зависит от сборки.

### 4.2. `sw.js`

Создать `shared/src/wasmJsMain/resources/sw.js`:

- при `install` читает `precache-manifest.json` и кеширует файлы;
- при `activate` удаляет старые кеши;
- навигация — network-first с фолбэком на `index.html`;
- остальные same-origin GET — cache-first;
- не кеширует non-GET и cross-origin.

### 4.3. Регистрация

Регистрировать `sw.js` только по HTTPS или на localhost.

## Этап 5. Домен и деплой

### 5.1. Домен

Заглушка: `<domain>`.

1. Зарегистрировать `<domain>` на reg.ru.
2. Сменить NS в reg.ru:
   ```text
   ns1.yandexcloud.net
   ns2.yandexcloud.net
   ```
3. Создать публичную зону `<domain>.` в Yandex Cloud DNS.
4. Создать запись:
   ```text
   <domain>. ANAME <domain>.website.yandexcloud.net
   ```
5. Создать бакет `<domain>`.
6. Включить хостинг статического сайта.
7. Выпустить сертификат Let's Encrypt в Certificate Manager.
8. Пройти DNS-проверку:
   ```text
   _acme-challenge.<domain> CNAME <cert-id>.cm.yandexcloud.net
   ```
9. Привязать сертификат к бакету.
10. Дождаться HTTPS.

### 5.2. Сборка

```bash
./gradlew :shared:wasmJsBrowserDistribution
```

Результат:

```text
shared/build/dist/wasmJs/productionExecutable
```

### 5.3. Загрузка

Переменные:

```bash
DOMAIN="<domain>"
BUCKET="$DOMAIN"
DIST="shared/build/dist/wasmJs/productionExecutable"
```

MIME-типы:

| Файл | Content-Type |
|---|---|
| `*.wasm` | `application/wasm` |
| `*.js` | `application/javascript` |
| `*.json` | `application/json` |
| `*.html` | `text/html; charset=utf-8` |
| `*.ttf` | `font/ttf` |
| `*.png` | `image/png` |

Cache:

| Файл | Cache-Control |
|---|---|
| `index.html` | `no-cache` |
| `sw.js` | `no-cache` |
| `manifest.json` | `no-cache` |
| `precache-manifest.json` | `no-cache` |
| `icons/*` | `public, max-age=86400` |
| хешированные ассеты | `public, max-age=31536000, immutable` |

Скрипт:

```bash
find "$DIST" -type f | while read -r f; do
  rel="${f#"$DIST"/}"

  case "$rel" in
    *.wasm) ct=application/wasm ;;
    *.js) ct=application/javascript ;;
    *.json) ct=application/json ;;
    *.html) ct="text/html; charset=utf-8" ;;
    *.ttf) ct=font/ttf ;;
    *.png) ct=image/png ;;
    *) ct=application/octet-stream ;;
  esac

  case "$rel" in
    index.html|sw.js|manifest.json|precache-manifest.json)
      cache=no-cache
      ;;
    icons/*)
      cache="public, max-age=86400"
      ;;
    *)
      cache="public, max-age=31536000, immutable"
      ;;
  esac

  aws s3 cp "$f" "s3://$BUCKET/$rel" \
    --endpoint-url https://storage.yandexcloud.net \
    --content-type "$ct" \
    --cache-control "$cache"
done
```

### 5.4. Проверка деплоя

```bash
curl -I https://<domain>/
curl -I https://<domain>/<file>.wasm
curl -I https://<domain>/sw.js
```

Ожидаемо:

- корень отдаёт `text/html`;
- `.wasm` отдаёт `application/wasm`;
- `sw.js` отдаёт `Cache-Control: no-cache`;
- HTTPS работает без предупреждений.

## Риски

1. **Compose wasm на iOS Safari.** Ввод текста и клавиатура требуют проверки на реальном iPhone.
2. **Версия iOS.** Нужен Safari 18.2+ из-за WasmGC. На проекте принят iOS 27.
3. **Вытеснение storage.** iOS может очистить Cache Storage и localStorage. Установленная PWA устойчивее, но гарантии нет.
4. **MIME-типы в Yandex Object Storage.** Неверный `Content-Type` для `.wasm` ломает запуск.
5. **Обновления service worker.** Старый кеш может жить до перезапуска PWA.
6. **DNS и сертификат.** Делегирование NS и выпуск Let's Encrypt могут занять до нескольких дней.
